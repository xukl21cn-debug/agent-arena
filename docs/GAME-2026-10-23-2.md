## 4. v0.4：双重威胁检测（已实现）

### 4.1 问题定义

`findHotPoints` 对每个空点只保留**最高级别的单一 effect**（win > open4 > four > open3）。落子同时制造多个独立威胁时，次要威胁被丢弃。四三杀的激活点因此降级显示为普通 `four` 候选；只按“挡 fiveAt”处理，会漏掉挡完后仍存在的活三开四。

同时，v0.3 prompt 第⑤条本来就要求“对手的 four 点：挡在其 fiveAt”，没有“可以等”的意思。第 22 手白方没有执行这条，是比字段缺失更直接的原因。v0.4 的 `double` 标记是加固：让模型无法再把四三杀当成普通 four。

### 4.2 实现

1. **数据结构**：`HotPoint` 增加可选字段
   - `double?: HotPointEffect[]`：`["four","open3"]`（四三杀）或 `["open3","open3"]`（双活三）；
   - `open3At?: Cell[]`：参与 double 的活三拆点。four+open3 时，占 double 点、挡 fiveAt、拆 open3At 一端都可能成立；双活三时只有占 double 点（或自己更快取胜）才挡得住，拆一端会留下另一个活三。

   例：第 21 手黑 `(4,7)` 的输出是
   ```json
   {
     "row": 4, "col": 7, "effect": "four",
     "fiveAt": [{ "row": 3, "col": 7 }],
     "double": ["four", "open3"],
     "open3At": [{ "row": 3, "col": 8 }, { "row": 7, "col": 4 }]
   }
   ```

2. **独立性判据**：同一方向的 four + three **不**合并——对手一手挡 fiveAt 就同时拆掉三。只有**不同方向**的 four + live three，或两个不同方向的 live three，才算 double；`win` / `open4` 不再重复标 double（现有 tier 已覆盖）。这样 T3 白 `(5,5)` 不会被误报：它的 three-window 与 four 在同一条竖线上，挡 `(6,5)` 同时解决两者。

3. **排序与优先级**：double 点在同级 effect 中排最前。提示词阶梯调整为：
   ```text
   own win > block opponent win > own open4 > block opponent open4
   > block opponent double > block opponent four > own double / own four / open3
   ```
   对手 double 本手优先占点；four+open3 可退而挡 fiveAt/拆 `open3At` 一端，双活三必须占点或自己更快取胜。对手 four 必须本手挡 fiveAt，不能等。自己的 double 是两步杀，但优先级低于立即 open4 和上述必防项。

### 4.4 行为级验收

在第 21 手局面下，agent 应选择拆点手：占 `(4,7)`，或挡 fiveAt `(3,7)`，或拆活三端 `(3,8)`；不能再下 `(8,10)` 这种发展棋。服务端测试保证字段和排序；LLM 行为用固定 prompt 的人工回放验收，不写成确定性的单元测试。
